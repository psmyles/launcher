# Step reference

Every step built into Launcher, by add-on. In a tool file a step is written `add-on.step "name" setting=value`; settings marked *needed* must be set (or asked each time). Generated by `cargo xtask docs` from `addons/*.kdl`; don't edit by hand.

## 3D Review (`review3d`)

Optimize FBX models into LODs, check them against a game engine's rules, and open them in 3D Review.

### Run an optimization preset — `review3d.run-preset`

Runs a preset saved from 3D Review's Opt workspace on FBX models, just as it was saved: its operations, its LODs and how it saves them. The results are saved as FBX files.

On its card: *Run {preset} on the models in {models}*

| Setting | Kind | |
|---|---|---|
| `preset` (Preset) | file | *needed*. .json files. A preset saved from 3D Review's Opt workspace (Save preset). |
| `models` (Models) | folder | *needed*. or a list of files an earlier step found. A folder of FBX models, one FBX file, or the models an earlier step found (an audit's Models to fix). |
| `subfolders` (Include the folders inside it) | tick-box | starts as `true` |
| `save-to` (Save to) | folder | *needed*. The results go here. Models found in a folder keep their place below it; models given one by one go straight in. |
| `if-there` (If the files are already there) | choice | starts as `Replace them` |
| `replace-models` (Let the results replace the models) | tick-box | starts as `false`. When Save to is the models' own folder and nothing is added to the file names, each model is replaced by its result, so a game engine that already uses it picks up the new one. There's no undo: keep the models in source control. |
| `suffix` (Add to each file name) | text | Advanced. For example _optimized. |
| `report` (Save the full report to) | file | .json files. Advanced. A JSON file with every figure, for a script or a pipeline. |

Gives back: `{name.files}` (Files saved, a list of files), `{name.skipped-models}` (Models skipped, a list of files), `{name.optimized}` (How many were done, a number), `{name.skipped}` (How many were skipped, a number)

### Audit models — `review3d.audit`

Checks FBX models against an audit preset saved from 3D Review's Aud workspace, and gives back the models that need fixing, for a next step to work on (Run an optimization preset, say).

On its card: *Audit the models in {models} with {profile}*

| Setting | Kind | |
|---|---|---|
| `profile` (Audit preset) | file | *needed*. .json files. An audit profile saved from 3D Review's Aud workspace (Save profile). |
| `models` (Models) | folder | *needed*. A folder of FBX models. One FBX file works too. |
| `subfolders` (Include the folders inside it) | tick-box | starts as `true` |
| `needs-fixing` (A model needs fixing when it has) | choice | starts as `Errors` |
| `stop` (Stop the tool when a model needs fixing) | tick-box | starts as `false`. Leave it off to carry on, so a next step can fix the models. |
| `report` (Save the full report to) | file | .json files. Advanced. A JSON file listing every finding, for a script or a pipeline. |

Gives back: `{name.to-fix}` (Models to fix, a list of files), `{name.passed}` (Models that passed, a list of files), `{name.to-fix-count}` (How many need fixing, a number), `{name.passed-count}` (How many passed, a number), `{name.checked}` (How many were checked, a number), `{name.errors}` (Errors found, a number), `{name.warnings}` (Warnings found, a number)

### Model stats — `review3d.model-stats`

Counts a model's polygons, triangles and vertices, as 3D Review's Model Stats shows them.

On its card: *Count what is in {model}*

| Setting | Kind | |
|---|---|---|
| `model` (Model) | file | *needed*. .fbx files. An FBX file. |

Gives back: `{name.polygons}` (Polygons, a number), `{name.triangles}` (Triangles, a number), `{name.vertices}` (Vertices, a number), `{name.gpu-vertices}` (GPU vertices, a number)

### Open in 3D Review — `review3d.open`

Opens a model in 3D Review. The tool carries on without waiting for it to close.

On its card: *Open {model} in 3D Review*

| Setting | Kind | |
|---|---|---|
| `model` (Model) | file | .fbx files. An FBX file. Leave it empty to just start 3D Review. |

## Bite (`bite`)

Run workflows saved from Bite on folders of images: resize, convert, adjust and more, with ImageMagick.

### Run a Bite workflow — `bite.run-workflow`

Runs a workflow saved from Bite on every image in a folder, and saves what it makes in another folder.

On its card: *Run {workflow} on the images in {images}*

| Setting | Kind | |
|---|---|---|
| `workflow` (Workflow) | file | *needed*. .bite files. A workflow saved from Bite (File > Save Workflow). |
| `images` (Images) | folder | *needed*. A folder of images. Bite works on the images in it, not those in the folders inside it. |
| `save-to` (Save to) | folder | *needed*. What the workflow makes goes here, whatever its outputs say in Bite. |
| `if-there` (If the files are already there) | choice | starts as `Do as the workflow says`. The workflow's outputs skip them, unless one was set to overwrite in Bite. |
| `stop` (Stop the tool when an image doesn't work) | tick-box | starts as `true`. Turn it off to carry on: the images that didn't work become a result, for a next step to list. |
| `jobs` (How many at once) | number | Advanced. How many images Bite works on at the same time. Leave it empty for one per processor core. |
| `report` (Save the full report to) | file | .json files. Advanced. A JSON file listing every file made and every image that didn't work, and why, for a script or a pipeline. |

Gives back: `{name.files}` (Files saved, a list of files), `{name.failed-images}` (Images that didn't work, a list of files), `{name.processed}` (How many were done, a number), `{name.skipped}` (How many were skipped, a number), `{name.failed}` (How many didn't work, a number)


## Core (`core`)

Run an app, remember a value, wait, or stop.

### Run an app — `core.run`

Starts an app with the words you give it, and shows what it prints.

On its card: *Run {program}*

| Setting | Kind | |
|---|---|---|
| `program` (App) | text | *needed*. Its name (found the usual way) or where it is. |
| `arguments` (What to pass it) | list | One item per word or path. |
| `command-line` (Everything to pass it, as one line) | text | Windows only: for apps that need it all as one line. |
| `cwd` (Cwd) | text | Working folder (default: the file's folder). |
| `stdin` (Text to type into it) | text | Typed into the app as it starts. |
| `wait` (Wait) | tick-box | starts as `true`. Wait for the program to exit. With #false it is started and left running (a game, an editor). |
| `timeout` (Timeout) | number | Give up (and stop the program) after this many milliseconds. |
| `expect-exit` (Answers that mean it worked) | text | starts as `0`. The numbers the app ends with when it works, like 0 or 0,1. |
| `io` (How its text is shown) | choice | starts as `auto`. auto, terminal (colours and progress bars) or plain. |
| `fail-if-output` (Stop if it prints) | text | Words that mean it went wrong, even if the app carries on. |

## Files and folders (`files`)

Copy, move, delete, find, read and write files and folders.

### Copy — `files.copy`

Copies a file, or a folder with everything in it.

On its card: *Copy {from} to {to}*

| Setting | Kind | |
|---|---|---|
| `from` (Copy what) | text | *needed*. The file or folder to copy. |
| `to` (To) | text | *needed*. Where the copy goes. End it with / to copy into that folder. |
| `overwrite` (Replace files that are already there) | tick-box | starts as `true`. Advanced. Replace files that are already there. |
| `ask-first` (Ask before replacing) | tick-box | starts as `true`. When the copy is already there, ask before replacing it. |

### Move or rename — `files.move`

Moves a file or folder, or gives it a new name.

On its card: *Move {from} to {to}*

| Setting | Kind | |
|---|---|---|
| `from` (Move what) | text | *needed*. The file or folder to move. |
| `to` (To) | text | *needed*. Where it goes. |
| `overwrite` (Replace a file that is already there) | tick-box | starts as `false`. Replace a file that is already there. |

### Delete — `files.delete`

Deletes a file, or a folder with everything in it.

On its card: *Delete {path}*

| Setting | Kind | |
|---|---|---|
| `path` (What to delete) | text | *needed*. The file or folder. |
| `missing` (If it isn't there) | choice | starts as `ok`. "ok" carries on; "error" stops. |
| `to-trash` (Move it to the Recycle Bin or Trash, so it can be got back) | tick-box | starts as `true`. Move it to the Recycle Bin or Trash instead of deleting it for good. |

### Make a folder — `files.make-folder`

Makes a folder, and any folders it sits in.

On its card: *Make the folder {path}*

| Setting | Kind | |
|---|---|---|
| `path` (Folder) | text | *needed*. The folder. |

### Find a file — `files.find-file`

Finds the first file whose name matches, and gives back where it is.

On its card: *Find {pattern}*

| Setting | Kind | |
|---|---|---|
| `pattern` (Name to look for) | text | *needed*. * stands for any letters, e.g. *.exe |
| `in` (Look in) | text | starts as `.`. Folder to look in. |
| `recursive` (Look in folders inside it too) | tick-box | starts as `false`. Look in sub-folders too. |
| `exclude-self` (Exclude self) | tick-box | starts as `true`. Never match the launcher's own executable. |
| `require-sibling` (Require sibling) | text | Only match when this also exists next to the file ({stem}, {name}, {ext}). |

### Read a file — `files.read`

Reads a text file, so later steps can use what it says.

On its card: *Read {path}*

| Setting | Kind | |
|---|---|---|
| `path` (File) | text | *needed*. The file. |

### Write to a text file — `files.write`

Writes text, a number or a list (one item per line) into a text file. Several steps can write to the same file, each after the one before, so a tool makes one file. Each run starts it afresh.

On its card: *Write to {path}*

| Setting | Kind | |
|---|---|---|
| `path` (File) | text | *needed*. Where to write it. A name like results.txt puts it next to the tool. |
| `heading` (Heading) | text | A line above what it writes, like "Models to fix". Leave it empty for none. |
| `content` (What to write) | long-text | *needed*. or a list, one item per line. Text, or what an earlier step found. A list goes in one item per line. |
| `format` (Format) | choice | starts as `text`. Advanced. text writes it as it is; json-pretty and json-compact re-format JSON. |
| `newline` (Line endings) | choice | starts as `keep`. Advanced. keep, lf (macOS and Linux) or crlf (Windows). |
| `create-dirs` (Make the folders it goes in) | tick-box | starts as `true`. Advanced. Create missing folders. |
| `append` (Add to what earlier steps wrote) | tick-box | starts as `true`. On: after what earlier steps of this run wrote to the file (the run's first write still starts it afresh). Off: replace the file. |
| `keep` (Keep what earlier runs wrote) | tick-box | starts as `false`. Advanced. With Add on: the file grows run after run, instead of starting afresh each run. |
